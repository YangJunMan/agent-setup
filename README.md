# agent-setup

코딩·비판적 검토·문서 작성·엔지니어링 기록에 사용하는 공통 agent 규칙이다.
**Markdown 파일 네 개를 프로젝트에 복사해 적용한다.** 설치 스크립트나 추가 도구는 필요 없다.

## 적용 방법

1. 아래 네 파일을 대상 프로젝트에 복사한다.
2. 같은 이름의 파일이 있다면 diff를 확인하고, 프로젝트 고유 지시를 보존하며 반영한다.
3. 새 agent 세션에서 어떤 규칙이 실제로 로드되는지 확인한다.

```text
project/
├── AGENTS.md
├── CLAUDE.md
└── .agent/
    ├── DISCUSSION_RULES.md
    └── DOCUMENTATION_RULES.md
```

갱신할 때도 diff를 확인하고 의도한 변경만 가져온다. 백그라운드 동기화는 없다.

**복사하지 않는 파일**

- `README.md`: 이 저장소의 안내 문서다. 대상 프로젝트의 README를 덮어쓰지 않는다.
- `.agent/ENGINEERING_LOG/`: 각 프로젝트의 작업 기록이다. 의미 있는 사건이 생기면 해당 프로젝트에서 agent가 날짜별 파일(`{repo}_{YYYY-MM-DD}_LOG.md`)로 생성하며, 공유·갱신 대상에 포함하지 않는다.
  (참고: 이 문구는 agent-setup → 신규 프로젝트로의 파일 복사 대상에서 제외한다는 뜻이며, 각 프로젝트에 이미 존재하는 로그를 `record` 저장소로 자동 수집하는 별도 자동화(GitHub App + Cloudflare Worker)와는 무관하다. 해당 자동화는 이미 push된 커밋만 읽으며 원본 저장소에 어떤 것도 stage·commit·push하지 않는다.)

이 저장소를 통째로 clone해 새 프로젝트의 출발점으로 사용했다면, 가져온 README와 engineering log는 제거한다. 기존 프로젝트의 문서와 기록은 보존한다.

### 전역 fallback 확인

전역 규칙이 `~/.config/agent-setup/DISCUSSION_RULES.md`를 fallback으로 지정한 환경에서는 프로젝트 규칙이 없을 때 구버전 사본이 로드될 수 있다. 실제로 이 문제가 발생한 적이 있다.

이 fallback을 사용한다면 중앙 저장소의 규칙과 동일하게 유지한다. 파일 배치만으로 적용을 보장할 수 없으므로, 새 세션에서 로드된 경로를 확인한다.

## 파일별 역할

| 파일 | 역할 | 로드 조건 |
|---|---|---|
| `AGENTS.md` | 코딩 4원칙, 응답 규칙, 상세 규칙의 로드 조건 | 항상 |
| `CLAUDE.md` | `@AGENTS.md` import | 항상 |
| `DISCUSSION_RULES.md` | 기존 제안에 대한 증거 기반 다중 모델 검토 | 사용자가 검토·토론을 명시 요청할 때 |
| `DOCUMENTATION_RULES.md` | 문서와 engineering log 작성법 | 문서 신규 작성·구조 변경·기록 작성 시 |

핵심은 **조건부 로드**다. 자주 쓰는 규칙은 상주시키고, 상세 규칙은 해당 작업에 필요할 때 읽는다. README와 engineering log는 상시 로드하는 규칙 파일이 아니다.

## 설계 배경

### 토론: agent 사이에 전달하는 내용을 제한한다

초기에는 두 agent가 전체 context를 주고받았다. grep 출력, tool call 기록, 중간 사고 과정, 이전 대화가 함께 전달되면서 한두 라운드 만에 토큰이 소진됐다. 결정과 무관한 내용까지 반복 전달된 것이 문제였다.

이를 줄이기 위해 전달 형식과 범위를 정했다.

| 단계 | 제한 |
|---|---|
| 요청 | 결정 하나, 제약, 판단 기준을 30줄 이내로 전달 |
| 증거 | 파일 경로를 전달하고, 접근할 수 없을 때만 필요한 부분 발췌 |
| 검토 결과 | verdict, 한 줄짜리 finding 최대 5개, 불확실성만 반환 |
| 반박 | 전체 리뷰 대신 이견이 있는 주장만 전달. 기본 1라운드, 새 증거가 있을 때만 2라운드 |
| 세션 | 리뷰어는 one-shot, orchestrator는 synthesis마다 compact |

토큰 절약의 초점은 규칙 파일의 길이보다 **전체 transcript의 반복 전달을 막는 것**에 있다.

### 코딩: 행동을 바꾸는 원칙을 보존한다

`AGENTS.md`는 [Karpathy Guidelines](https://x.com/karpathy/status/2015883857489522876)의 네 원칙을 유지한다.

- 고민 후 코딩
- 단순함 우선
- 최소 침습 수정
- 목표 기반 실행

이 원칙을 유지한 이유는 요청 밖 변경과 과도한 복잡화가 줄고, 필요한 질문이 구현 전에 나오는 효과를 diff에서 관찰했기 때문이다.

규칙을 줄일 때도 다음처럼 행동을 바꾸는 세부 지시는 보존한다.

- 기존 dead code는 임의로 삭제하지 말고 언급한다.
- 작성한 코드를 다시 읽고 줄일 수 있는지 확인한다.
- 계획의 각 단계에 검증을 붙인다.

이전 재작성에서는 일부 지시가 빠져 복원해야 했다. 따라서 압축한 규칙은 반드시 원본과 대조한다.

### 문서: 중복은 줄이고 증거는 남긴다

반복 요약, 빈 템플릿, 중복 메타데이터, 근거 없는 수식어는 문서를 읽을 때마다 context를 차지한다.

문서 규칙은 다음에 집중한다.

- 목적이나 결정을 먼저 쓴다.
- 하나의 사실은 한 곳에 두고 다른 곳에서는 연결한다.
- 재현에 필요한 증거는 보존한다.
- 미사여구와 중복 표현을 제거한다.
- engineering log는 항목당 12줄 이내로 작성한다.

AI가 필요한 정보를 적은 비용으로 찾고, 사람도 빠르게 읽을 수 있는 문서를 목표로 한다.
